Overview

Brim is a native macOS app written in Swift with SwiftUI and AppKit. It sits in the notch at the top of a MacBook display, where the pointer already goes. While something is live, such as music or an agent waiting on you, the notch widens to show it. When you want more, a rounded black panel grows down out of the notch.

It runs locally with no account, no analytics, and no Dock or menu bar icon. On a display without a notch, Brim lives in a slim handle at the top center of the screen.

Requirements: macOS 14 Sonoma or later. The main target is an Apple Silicon MacBook with a notch; any Mac works through the handle.

Features

A small window shell with pluggable modules. The shell decides when the panel opens; modules decide what it shows.

🎵

Live notch

Artwork and a waveform beside the notch while media plays; an orange or red glyph when an agent waits or fails. Invisible when nothing is live.

🖥️

Out of the way

Hides on any display where an app is full screen and returns when you leave. Choose all displays, the notched one or the main one.

👆

Opens your way

Hover or click the notch, scroll down on it, or press a global shortcut that opens the panel ready for typing.

↔️

Gestures

Scroll down to open and up to close. Swipe the media ears left or right to skip tracks without opening anything.

📥

Drag and drop

Drag files or text to the notch and the panel opens into drop zones for the modules that accept them.

🧩

Modules

Each enabled module gets its own card and the panel widens to fit. Turn them on, off and reorder them in Settings.

Install and run

Brim is built from source; there is no signed download yet. You need the Xcode command-line tools (Swift 5.10 or later) and, for the first build only, CMake and network access to build the media helper.

xcode-select --install       # if you don't have the command-line tools
brew install cmake           # first build only

git clone https://github.com/TeraSurror/brim.git
cd brim
./build.sh                   # builds build/Brim.app (release, ad-hoc signed)
open build/Brim.app

To keep it, copy build/Brim.app to /Applications and turn on Settings → General → Launch at login.

CommandWhat it does
./build.shRelease build of build/Brim.app, ad-hoc signed
./build.sh debugDebug build of the same bundle
BRIM_SKIP_MEDIA_ADAPTER=1 ./build.shBuild without the media helper (no CMake); everything except Now Playing works
./scripts/build-media-adapter.sh --forceRebuild the media helper
swift build / swift testCompile, or run the unit tests (no helper needed)

On first launch Brim opens Settings with a short welcome note, because a quiet notch shows nothing until something plays. Open Brim again at any time (Finder, Spotlight or open -a Brim) to bring Settings back.

Ad-hoc signing: every rebuild looks like a new app to macOS, so granted Automation and the login item can be dropped; re-grant them after a rebuild. macOS notification banners also need a signed build, so the development build uses Brim's own notch alert instead.

Settings

  • General: open on hover or click, hover and collapse delays, the global shortcut, the live notch, which displays show Brim, launch at login.
  • Media: Now Playing on or off, which player to follow, Automation.
  • Agents: Agent Status, the Claude Code connection, alerts, how long finished sessions stay, the socket for other tools, and Quick Prompt's claude location.
  • Modules: turn modules on or off and reorder them.
  • About: version and Copy Diagnostics for bug reports.

Settings are stored as versioned JSON in ~/Library/Application Support/Brim/settings.json. Unreadable files are moved aside, never deleted.

Keyboard shortcut

Record one in Settings → General → Keyboard → Open Brim; there is no default, so it never collides with another app. It opens the panel on the display under the pointer without switching away from your app, stays open while you work in it, and closes with Esc, the shortcut again, or a click elsewhere. It also opens over a full-screen app, because you asked for it.

Connecting coding agents

Turn on Agent Status in Settings → Agents. Brim opens a Unix socket at ~/Library/Application Support/Brim/agent.sock (owner-only, removed on quit) and accepts brim://agent links. Nothing leaves the Mac.

Claude Code

Settings → Agents → Claude Code → Connect… shows exactly what changes, then writes ~/.brim/claude-hook.sh, backs up ~/.claude/settings.json and adds Brim's hooks next to yours. Start a new Claude Code session afterwards. Update… appears when an older hook is installed; Disconnect… removes it.

Any other tool

Write one JSON object per line to the socket:

printf '%s\n' '{"agent":"codex","session":"demo","status":"working","title":"Fix the parser","detail":"Running tests"}' \
  | nc -U "$HOME/Library/Application Support/Brim/agent.sock"

or open a link:

open -g 'brim://agent?agent=codex&session=demo&status=waiting&title=Approve%20a%20tool%20call'
FieldRequiredMeaning
agentyesTool identifier, e.g. claude-code, codex, cursor
sessionyesStable ID for one session
statusyesworking, waiting, done or error
title, detailnoShown on the row (trimmed and length-limited)
costUSDnoSession cost so far
cwdnoProject folder; rows and alerts can open it in Finder
appnoBundle ID of the terminal or editor. Validated, never executed; alerts switch to it
timestampnoISO 8601; older events never overwrite newer ones

brim://agent?action=dismiss&agent=…&session=… removes one row and action=clear clears the list. Waiting sessions sort first, then failures, working and done; finished sessions disappear after 10 minutes (adjustable).

Alerts

A separate opt-in. When a session newly needs input or fails while the panel is closed, a card drops from the top of the screen you are on, or a macOS banner appears on a signed build. Clicking it brings the session's terminal or editor forward.

Quick Prompt

Ask Claude from the notch, using the Claude Code you already have. Turn it on in Settings → Modules; Brim explains what it does first, and there is no macOS permission.

  1. Open the panel. The shortcut puts the cursor straight in the prompt field. Type your question.
  2. Pick what Claude may read with the folder chip: the project of your most recent agent session (the default), a recent folder, any folder, or none for plain chat.
  3. Press Return. The answer streams in place of the cards, with lists and code rendered and a Copy button. Ask follow-ups in the same bar; New starts over; Done or Esc returns to the cards.

Close the panel while Claude is answering and the notch shows a quiet working glyph, then a check mark until you look.

Read-only by design. Brim runs your claude CLI with only Read, Grep and Glob and no MCP servers. Claude can read files in the chosen folder but cannot edit files, run commands or fetch from the web. The prompt goes in on standard input, never through a shell. Brim itself makes no network request; Claude Code does, under your login.

Privacy and permissions

  • No network access from Brim. Media, agents and settings stay on the Mac. Quick Prompt's traffic belongs to Claude Code and happens only when you send a prompt.
  • No analytics, ever.
  • No permission prompts at launch. A feature asks only when you turn it on, after an explanation, and keeps working in a limited form if you decline.

Now Playing uses the third-party ungive/mediaremote-adapter v0.7.7 (BSD-3), built from a pinned commit and run as a separate process through /usr/bin/perl. It is never linked into Brim and stops when Brim quits.

Architecture rules

  • One NSPanel per screen, rebuilt when displays change.
  • AppKit stays in Window/ and App/; State/ is pure and driven by an injected clock, so tests use a fake one.
  • Every system API sits behind a protocol with one real implementation and one fake.
  • Features are BrimModules that plug in without touching the window shell.
  • Settings changes bump the schema (currently 7) and add a migration step with a test.
  • No third-party dependencies without asking first.

The full guide is AGENTS.md. The manual testing checklist and progress log live in the repository.

Troubleshooting

When reporting a bug, include Settings → About → Copy Diagnostics.

The panel does not appear
  • Check Brim is running: pgrep -fl '/Brim.app/Contents/MacOS/Brim'
  • Move the pointer to the very top edge, inside the notch, or onto the handle on other displays.
  • Open the panel may be set to "On click"; hovering then does nothing.
  • Show Brim on may exclude this display.
  • Brim hides on purpose while an app is full screen on that display. Your shortcut still opens it.
Media does not appear
  • Turn it on in Settings → Media; it asks for nothing.
  • The ears hide 3 seconds after playback pauses; an agent that needs you takes priority.
  • Check the helper: pgrep -fl 'mediaremote-adapter|brim-media-supervisor'. If it is missing, run ./scripts/build-media-adapter.sh --force and rebuild. A running Spotify or Music still works through Automation.
Agents do not appear
  • Turn on Agent Status, then press Show a Test Session. If that row appears, the problem is the integration.
  • Check the socket: ls -l "$HOME/Library/Application Support/Brim/agent.sock", then send the nc -U example.
  • After connecting Claude Code, start a new session.
  • brim:// links need the app launched once so macOS registers it.
Alerts do not appear
  • Turn on Alert when an agent needs input or fails.
  • Alerts fire only when a session newly waits or fails, and only while no panel is open.
  • On the development build, look for Brim's card at the top of the screen, not in Notification Center.
Quick Prompt can't find claude

Install Claude Code and run claude once in Terminal to log in. If it lives somewhere unusual, choose it in Settings → Agents → Quick Prompt → Choose….

The shortcut does nothing

Settings warns when macOS refuses a combination. ⌃⌥Space is macOS's "next input source" shortcut; choose another combination if you use several input sources.

A rebuild dropped a permission or the login item

Ad-hoc builds look new to macOS after every rebuild. Re-grant Automation in System Settings → Privacy & Security and toggle Launch at login off and on.
